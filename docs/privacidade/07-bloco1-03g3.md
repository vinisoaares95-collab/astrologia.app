## 2. Limitador: HMAC e expiração

**Chave do cliente** (`src/features/palm-reading/server/client-key.ts`):

- **Como é feita:** HMAC-SHA256 com o segredo `SIDERA_CLIENT_KEY_SECRET`
  (≥ 32 caracteres) aplicado a `client:<ip>`. Substitui o SHA-256 simples.
- **Natureza do dado:** continua sendo dado pessoal pseudonimizado.
- **O que não fica registrado:** o IP original não é guardado nem vai a
  log.
- **Fora de produção:** sem o segredo, usa um segredo aleatório do
  processo.
- **Em produção:** sem o segredo, não há chave e os endpoints respondem
  **503**.

**Expiração** (`rate-limit.ts`):

- **Quando a chave sai:** quando todos os horários dela saem da janela.
- **Quando a limpeza roda:**
  - a cada uso, no máximo uma vez por minuto;
  - por um temporizador, enquanto houver chaves. Ele não segura o
    processo e para quando a memória esvazia.
- **Duração máxima:** janela + 1 minuto após a última tentativa (1 h + 1
  min nos limites atuais), mesmo sem tráfego.

## 3. Fronteira de confiança do IP

**O HMAC não resolve a falsificação.** `x-forwarded-for` chega do
cliente; só a parte escrita pelo proxy de confiança é confiável.

Comportamento por configuração:

| Configuração                                                    | Fonte do IP                                                                                       | Uso                                                                                    |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `SIDERA_CLIENT_IP_HEADER=<nome>`                                | o valor desse cabeçalho, que o proxy de confiança **sobrescreve**                                 | produção, quando a hospedagem documentar esse cabeçalho                                |
| `SIDERA_TRUSTED_PROXY_HOPS=N` (1–5)                             | a N-ésima entrada **da direita** de `x-forwarded-for` (os N proxies de confiança **acrescentam**) | produção, quando a hospedagem documentar quantos proxies acrescentam                   |
| nenhuma, fora de produção                                       | primeiro `x-forwarded-for`, depois `x-real-ip` (como antes)                                       | desenvolvimento e avaliações; **falsificável**, aceito por não haver exposição pública |
| nenhuma, as duas ao mesmo tempo, ou valor inválido, em produção | —                                                                                                 | **503**: não há como limitar por cliente com segurança                                 |

**Regras comuns a todas as fontes:**

- valores que não são IP são descartados;
- sem IP válido, todos dividem a mesma cota, para que forjar lixo não dê
  cota nova.

**O que depende da hospedagem, ainda não definida (H5):**

- **Qual opção usar:** só a documentação do provedor diz se há um
  cabeçalho sobrescrito ou quantos proxies acrescentam a
  `x-forwarded-for`. **Nenhum valor foi presumido.**
- **Várias instâncias:** os limites continuam em memória, um por processo.
  O estado compartilhado (H9/T7) fica para o Bloco 3.
- **Mudança de comportamento:** o modo simulado em produção
  (`NODE_ENV=production`) agora exige também `SIDERA_CLIENT_KEY_SECRET` e
  uma das duas fontes. O modo real já era bloqueado em produção.

**Configuração mínima para produção** (quando houver hospedagem):

```
SIDERA_CONSENT_SECRET=<≥ 32 caracteres, aleatório>
SIDERA_CLIENT_KEY_SECRET=<≥ 32 caracteres, aleatório, diferente do anterior>
SIDERA_CLIENT_IP_HEADER=<cabeçalho documentado pelo provedor>   # ou
SIDERA_TRUSTED_PROXY_HOPS=<nº documentado pelo provedor>
```

Os segredos ficam no gerenciador de segredos da hospedagem, nunca no
repositório. Trocar o segredo do HMAC zera os limites em vigor, o que é
aceitável.

## 4. Logs

O teste fica em `src/features/privacy/app-logs.test.ts`. Ele cobre **só os
logs escritos pelo código do Sidera** (`console.*`), em duas camadas.

**Estática:**

- **Inventário fechado:** os únicos `console.*` fora de testes são os dois
  já revisados:
  - o tipo do erro inesperado do mapa;
  - as versões da base de fusos.
- **Toda chamada nova quebra o teste** até ser revisada.
- **Leitura das mãos:** nenhum `console.*`.
- **Argumentos:** nenhuma chamada recebe ambiente, pedido, corpo, recibo
  ou entrada.

**Execução, com marcadores:**

- **Leitura das mãos:** consentimento, análise bem-sucedida, falha do
  provedor e pedido malformado não registram nada. Nenhum destes aparece:
  - o recibo;
  - um trecho da foto;
  - o segredo e a chave de API;
  - o IP.
- **Dados de nascimento:** a falha da base de fusos registra só as
  versões; data, hora e local não aparecem.
- **Mapa:** o erro inesperado registra só o tipo do erro, nunca a mensagem
  (que no teste continha data, hora e cidade).
- **Dados válidos:** nada é registrado.

**Fora do alcance destes testes:**

- **Infraestrutura:** os registros da hospedagem (acesso, proxy,
  plataforma, observabilidade). Precisam ser verificados no provedor (H3,
  H4).
- **Framework:** erros que o próprio Next.js registre fora do código do
  Sidera. Exemplo: uma exceção não tratada em Server Action, que as ações
  atuais capturam.
- **Ambiente local:** os testes rodam aqui e não garantem nada sobre a
  infraestrutura de produção.
